# Adding a flow across the ERP boundary

## 1. Classify it first

Every flow is **projected** or **read-through**. Choosing wrongly is expensive to undo, and the choice is per flow, never per system.

| Ask | Projected | Read-through |
|---|---|---|
| Is it on an anonymous request path? | yes → projected, always | — |
| Does a wrong value cost money or credit? | — | yes → read-through |
| Is the query shape a listing, search or facet? | yes | — |
| Is it consulted only at cart or checkout? | — | yes |

If projected, it needs a staleness budget written into `commerce-platform/packages/contracts/src/index.ts` and a lag metric that asserts it. If read-through, it must return the provenance envelope and have a defined behaviour when the dependency is gone.

## 2. Contract first, code second

The shape belongs in `commerce-platform/packages/contracts` before anything is implemented here. Use that repository's `contract-change` skill, publish a release, then raise `CONTRACT_PIN` here and run `npm run contract:check`.

Implementing against an unreleased shape means the pin gate cannot protect you from it changing.

## 3. Go through the shared client

Never call Business Central with a bare `fetch`. The shared client carries token acquisition, correlation-id propagation, `Retry-After` handling and the circuit breaker. A direct call bypasses all four, and the bypass is invisible until an incident.

## 4. Bulk, with a cap

A read-through flow over lines is defined on a **collection**, capped at 100, with no single-line variant. Offering one guarantees a caller loops over it and turns a basket into N round trips against a throttled ERP.

## 5. Writes are staged and idempotent

- The key is generated by the originating business action, not by the transport, and is stable across every retry of that action.
- The connector enforces uniqueness with a database index. A duplicate arrival fails on that index — catch it and return the original result rather than surfacing a conflict to the caller.
- Return `202` and a platform-side identifier. Never confirm what was not committed.

## 6. Define the degraded behaviour, and test it

Write down what happens when Business Central is unreachable, and add the dependency-down case to the tests. Read paths degrade, write paths queue, money and credit fail closed. A flow without a tested degraded path is a flow that will be discovered during an outage.

## 7. Keep the boundary

No ERP table, field or enum name may appear outside the mapping. If a domain service needs to know that a field is called `Sell-to Customer No.`, the mapping has leaked.
